# 性能与验证记录

以下内存历史数据测于 2026-11-23；preview.3 的闲置查询观察测于 2026-11-26。数据不保证在其他机器上完全复现。

## 测量口径

使用 Windows 进程计数器 `WorkingSet64`、`PrivateMemorySize64`、`TotalProcessorTime`、`HandleCount` 和 `Threads.Count`。每秒采一次，约 36 秒，覆盖至少一个 30 秒电量查询周期。内存以 PowerShell `1MB`（1,048,576 字节）换算。

| 版本 | 工作集 MiB | 私有内存峰值 MiB | CPU 时间增量 | 时长 | 线程 |
|---|---:|---:|---:|---:|---:|
| 早期 .NET / WinForms | 69.88–70.23 | 33.20 | 15.62 ms | 36.4 s | 28 |
| 1.3 原生、单型号 | 14.95–14.99 | 2.96 | 0 ms | 36.5 s | 5 |
| 1.4 多协议预览 | **14.78–14.79** | **3.05** | **0 ms** | 36.5 s | 4 |

1.4 的句柄数量为 183–183。原始采样数据见 [performance-sample.json](performance-sample.json)。这是 G75 V2 的 CZ 路径采样，不是所有协议同时运行时的压力测试。

CPU 增量为 0 ms 表示本次采样低于该计数器可分辨精度，不代表程序绝对不消耗 CPU。早期版在 20 个逻辑处理器上整机平均约 0.0021%。

## 为什么省内存

运行时没有 .NET / WinForms / Python / Electron / WebView。图标嵌入资源，菜单临时创建，查询由一个工作线程处理；操作系统 DLL 可能另有自身线程。程序等待事件和定时器，不忙轮询。有效接口优先复用，状态不变不重复生成图标或写诊断文件。没有调用强制工作集裁剪 API。

## 已验证

- G75 V2，新版 3837:3033 2.4G 接收器：获得有效电量并与原始应答一致。
- 充电状态曾观察到原始 `0xE4`（100% + charging），界面改为蓝色闪电；拔线后恢复数字。
- 150% 显示缩放下实际菜单 DPI=144、372×366 像素，与 248×244 DIP 设计一致。
- 100% / 125% / 150% / 200% 菜单绘制预览。
- 菜单导航、Esc 关闭、F5 刷新、右键回调与失焦关闭。
- 菜单连续开关 12 次，GDI 对象 14 → 14。
- 协议帧解析、校验、序号、身份过滤、充电显示规则、全部图标和蓝牙 ABI 的离线测试。

## 1.4.0-preview.2：加入调色盘后的实测

原生设置窗口按需创建，在同一深色窗口内以 GDI 绘制色板、色相条和颜色预览。不加载额外的系统选色弹窗或外部 UI 框架。色板位图关闭窗口时释放；图标在非默认配色时通过 GDI 保留原 Alpha 重新着色，状态和颜色没变化时不重复生成。

| 使用状态 | 时长 | 工作集 MiB | 私有内存峰值 MiB | CPU 时间增量 |
|---|---:|---:|---:|---:|
| 实际操作内置 GDI 调色窗口并关闭之后 | 36.5 s | 14.85–14.88 | 3.07 | 0 ms |

句柄数 182–183，线程数 5（包括系统 DLL 的线程）。CPU 时间为 0 ms 仍表示低于本次计数器精度，不是绝对零占用。应用没有调用工作集裁剪 API；系统页回收和字体缓存会影响实际计数。

原始数据：[使用调色窗口后](palette-post-use-sample.json)。

新增验证：HEX / RGB 双向联动、非法输入阻止保存、三状态独立颜色、色板与色相拖拽、取消不改设置、保存立即生效、重启恢复、恢复默认后取消不保存、Esc 取消；设置窗口开关 12 次，GDI 对象 14 → 14。图标在多种像素尺寸下验证了非对称 RGB 通道、预乘 Alpha 和透明背景。

## 仍需实机验证

preview.3 在本机 G75 V2 接收器上先手动读取成功，再连续观察 **187.50 秒**：设备命令调用 **1 → 1**、自动查询 **0 → 0**，UI 定时器 **6 → 43**。说明定时器仍工作，但闲置不再发查询。两个 Raw Input 键盘接口均能关联到正确电量接收器。离线测试覆盖输入过期、物理设备不匹配、系统挂起、手动请求和禁止发送条件。原始查询计数见 [standby-idle-sample.json](standby-idle-sample.json)。

这次观察不是新的内存基准，未操作调色窗口；系统页回收也让工作集波动，因此不拿它替换上面的旧版内存数据。实际键盘进入待机、待机后的首个按键自动更新、其他型号的待机表现仍需用户确认。

其他型号和固件、QHW、旧款 USB / 接收器、蓝牙键盘、有线切换、真实多屏 DPI 切换、长期运行和睡眠恢复。蓝牙没有可用缓存时应显示未取得读数，不能将离线测试通过当作设备兼容承诺。
